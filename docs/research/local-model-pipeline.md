# Local transcription and cleanup options

Researched September 19, 2026 against upstream documentation and source. This first-pass runtime comparison predates the completed model requirements. The [offline model research](requested-offline-models.md) adds the requested Cohere path, and [S1-mini availability](s1-mini-availability.md) covers the mandatory cleanup model. Runtime choices remain open. The sources describe moving branches, so implementation must pin and test a release.

Amanuensis can support imported local models without an account or usage allowance. The practical constraint is compatibility. A downloaded model must match an implemented runtime, architecture, tokenizer, and file format. The importer should explain missing files or unsupported formats instead of presenting a generic locked state.

## Vocabulary and replacements

Vocabulary is recognition guidance. WhisperKit exposes prompt tokens; whisper.cpp accepts an initial prompt with a bounded token budget. These provide context rather than a guarantee that every custom term will appear. Argmax advertises additional custom-vocabulary functionality in its Pro SDK, so the OSS prompt API must not be presented as equivalent to that feature. [WhisperKit options](https://github.com/argmaxinc/argmax-oss-swift/blob/main/Sources/WhisperKit/Core/Configurations.swift), [whisper.cpp prompt fields](https://github.com/ggml-org/whisper.cpp/blob/master/include/whisper.h), [Argmax OSS/Pro distinction](https://github.com/argmaxinc/argmax-oss-swift).

FluidAudio documents CTC-based vocabulary rescoring with acoustic evidence and aliases. Parakeet TDT 0.6B requires an additional CTC encoder for this path. Streaming has weaker multi-word and cross-chunk handling, and short terms can produce false matches. Evaluate examples such as Aritra, Amanuensis, Convex, and ordinary near-sounding words. Do not reuse published benchmark percentages as promised application accuracy. [FluidAudio custom vocabulary](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/ASR/CustomVocabulary.md).

Replacements should be a separate deterministic operation owned by Amanuensis: for example, `super whisper` becomes `Superwhisper`. Recommended semantics are whole-word or phrase matches, explicit case behavior, longest match first, and one pass to prevent replacement chains. Store the raw transcript separately. Apply replacements once to the selected final text, whether that is a successful cleanup result or the raw transcription. Give cleanup vocabulary guidance separately so replacement output never becomes input to a second replacement pass. These are proposed product rules and need examples in the eventual specification.

## Optional local cleanup

Two viable approaches remain open:

- Embed `MLXLLM` from MLX Swift LM. It uses supported Swift architecture implementations, MLX-loadable `safetensors`, configuration, tokenizer, and generation metadata. A model being available on Hugging Face is insufficient. Current package minimum is macOS 14 with Swift tools 6.2; MLX focuses on Apple Silicon. This keeps processing in the app but requires budgeting model and context memory. [Compatibility guide](https://github.com/ml-explore/mlx-swift-lm/blob/main/Libraries/MLXLMCommon/Documentation.docc/model-compatibility.md), [package requirements](https://github.com/ml-explore/mlx-swift-lm/blob/main/Package.swift), [MLX Swift](https://github.com/ml-explore/mlx-swift).
- Connect to a user-selected local service such as Ollama, whose chat endpoint accepts a model and messages. This lets an existing local installation own model loading but adds service availability and request errors. An explicit loopback endpoint and local model should be required for a mode labeled local. Do not automatically replace an unavailable local service with a cloud endpoint. [Ollama chat API](https://docs.ollama.com/api/chat).

Recommended processing sequence: capture audio, transcribe, retain raw text, optionally clean up using the selected mode, apply replacements once, apply insertion settings. Voice-to-text mode can bypass cleanup entirely. Cleanup must receive a bounded instruction to preserve meaning and return only the reformatted text.

If cleanup times out, fails, or exceeds a configured output bound, keep the successful transcription available and report that cleanup failed. Preserve raw and cleaned text as separate values; never overwrite raw text with partial generation. For automatic insertion after a runtime failure, use the transcription with deterministic replacements as fallback. Empty output needs model-specific handling: S1-mini deliberately returns nothing for filler-only input. If transcription itself fails, report the error and retain audio according to the user's retention policy. These are recommended failure semantics, not features inherited from a runtime. The subsequent [S1-mini availability research](s1-mini-availability.md) records the user's required cleanup model and its verified public distribution.

## Speaker labeling

Local diarization is feasible as an additional processing stage. FluidAudio offers offline and streaming pipelines; its guide describes different speaker-count, overlap, and latency tradeoffs. The current guide also documents a macOS 14 BNNS crash under particular compute routing. That requires reproduction on the chosen release and target hardware before promising support. [FluidAudio diarization guide](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/Diarization/GettingStarted.md).

Argmax now includes a separate open-source SpeakerKit product using Pyannote, with local model loading and a helper that combines speaker intervals with WhisperKit transcripts. Thus speaker labeling does not require buying the Pro SDK, though Pro streaming features are separate. [SpeakerKit](https://github.com/argmaxinc/argmax-oss-swift#speakerkit).

Proposed first behavior: optional speaker labels for meeting recordings, with editable `Speaker 1` names. Detecting a voice cluster does not establish a person's identity. Let transcription succeed when diarization fails. Benchmark overlapping voices and quiet participants before choosing a diarizer, and keep microphone/system tracks available separately during processing where capture allows it.

## Licenses and validation before selection

Runtime and model licenses are separate metadata. Argmax OSS and whisper.cpp use MIT; FluidAudio uses Apache-2.0; MLX Swift LM uses MIT. The inspected FluidInference Parakeet v2 model card declares CC-BY-4.0. Do not infer a model's license from the SDK license. Record the exact model source, revision, and license when selecting distributable defaults. [Argmax license](https://github.com/argmaxinc/argmax-oss-swift/blob/main/LICENSE), [whisper.cpp license](https://github.com/ggml-org/whisper.cpp/blob/master/LICENSE), [FluidAudio license](https://github.com/FluidInference/FluidAudio/blob/main/LICENSE), [MLX Swift LM license](https://github.com/ml-explore/mlx-swift-lm/blob/main/LICENSE), [Parakeet v2 model card](https://huggingface.co/FluidInference/parakeet-tdt-0.6b-v2-coreml).

Before selecting defaults, measure cold load, warm dictation latency, peak memory, and transcription quality on the target Mac. Include silence, very short phrases, long recordings, names, code terms, and cleanup that must preserve numbers and negation. Exercise cancellation, missing model components, corrupted imports, absent local services, and offline startup with empty caches. No benchmark or runtime execution was performed in this research pass.
