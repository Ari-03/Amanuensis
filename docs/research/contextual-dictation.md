# Contextual dictation references

Researched September 19, 2026. Scope: desktop UX in Wispr Flow and Willow, with lessons for an English-only, local-first Mac app. These are documented product behaviors, not hands-on test results. Suggestions below are proposals for Amanuensis.

## Offline, context, and storage boundaries

Flow requires internet for transcription. Its current data guide explicitly says disabling model improvement still uses cloud processing. Local history retention and cloud storage are separate settings. A local history switch must therefore never be interpreted as offline inference. [Product overview](https://docs.wisprflow.ai/articles/2772472373-what-is-flow), [data controls](https://docs.wisprflow.ai/articles/9609615338-Private-Cloud-Sync-and-Data-Sharing-preferences-in-Wispr-Flow)

Flow's context feature reads surrounding text and detects browser websites. Its documentation also lists broader context, including screenshots and conversation content. Official pages disagree about whether context has its own toggle: the September 19 data guide says yes, while the older privacy article says no. Treat the exact current control as unverified without inspecting the installed version. [Context awareness](https://docs.wisprflow.ai/articles/4678293671-Context-Awareness), [current data controls](https://docs.wisprflow.ai/articles/9609615338-Private-Cloud-Sync-and-Data-Sharing-preferences-in-Wispr-Flow), [conflicting privacy article](https://docs.wisprflow.ai/articles/3842996553-privacy-mode-private-cloud-sync)

Willow's July 2026 plan guide includes offline dictation in Individual Pro, and its homepage describes processing entirely on the device. Its November 2025 privacy guide instead explains cloud processing, default private mode, local transcript history, and optional reading of nearby cursor text. The newer sources establish an offline offering, but these pages do not identify its model, platform coverage, or which cleanup features remain available offline. Calling Willow cloud-only would be inaccurate; assuming offline and cloud feature parity would also be unsupported. [Plans](https://help.willowvoice.com/en/articles/12854184-willow-pricing-plans-overview), [homepage](https://willowvoice.com/), [privacy guide](https://help.willowvoice.com/en/articles/12854269-how-willow-protects-your-data-and-privacy)

## Suggestions for Amanuensis

- Keep the user's editable recording shortcut on Home. Add a small practice field after permissions and model download so setup verifies the whole path from microphone to inserted text.
- Treat a mode as an explicit user choice. App rules can select that mode automatically, but the recording indicator should show which mode won and allow an override. Capture the target app when recording starts so opening the settings window does not change the intended destination.
- Keep app detection separate from reading document contents. Matching a native app to an email mode should not silently enable screen reading. Website rules can arrive later if reliable URL detection requires more access.
- Show examples beside tone choices. "Casual" is ambiguous; a preview makes punctuation, capitalization, and rewriting visible. Preserve a voice-to-text preset with cleanup disabled.
- Separate vocabulary, replacements, and future text snippets. Explain recognition hints as hints. Use explicit replacement rules for spelling guarantees, with whole-word matching, longest-match precedence, and a preview before saving.
- Preserve raw transcription alongside cleaned output when history is enabled. Offer undo-cleanup and copy-last-result recovery so a model rewrite or paste failure does not waste a recording.
- Use the floating pill and optional notch presentation to show distinct recording, processing, ready, and failure states. Give stop and cancel visible controls. Neither product's cited documentation proves notch integration; that remains a separate Mac feasibility question.
- Display transcription and cleanup execution locations separately. A local speech model plus cloud cleanup still sends text away. Keep downloaded local models usable without an account or subscription, as requested.

The strongest borrow is recoverability. Tone presets save edits, but a visible active mode, undoable cleanup, and a recoverable transcript make the app dependable when inference or insertion goes wrong.
